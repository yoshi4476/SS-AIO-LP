# 問い合わせの集約について（対応済み）

3サイトの問い合わせは、すでに**管制塔GAS 1つ・スプレッドシート1枚**に集まっている。
転送用のコード（forward-to-hub.gs）を各サイトへ配る作業は**不要**。

## 調べて分かったこと

管制塔GASと、各サイトのフォーム受付は**最初から同じApps Scriptプロジェクト**だった。
デプロイURLが11個あり、そのうち1つをコーポレートと補助金サイトのフォームが使っていた。
別々のGASだと思っていたのは、URLが違うだけだった。

## いま動いている形

```
各サイトのフォーム
  └→ 同じGAS（管制塔）の doPost
       ├ action あり  → KW台帳・記事ログ・KPI（記事工場から）
       └ action なし  → form_()（contact.hub.gs）で種別ごとに受付
                          └→ 管制塔スプレッドシートの「問い合わせ」タブ
```

| 種別 | 判定 | 記録内容 |
|:--|:--|:--|
| 問い合わせ（contact） | 本文に「補助金」「見積」等があればHOT、なければWARM | 相談内容 |
| 無料診断（diagnosis） | HOT | 診断の種類・総合点・判定・項目別スコア |
| サイト無料診断（site_audit） | HOT | 対象URL・総合点・判定 |

同じメールから24時間以内の再送信は、新しい行を作らず既存行にまとめる。
温度は高い方を残す（診断を出した人が後から相談してきても下がらない）。

## コードを直したとき

```
python scripts/gas_deploy.py hub
```

配布とデプロイまで通る。Apps Script エディタを開く必要はない。
