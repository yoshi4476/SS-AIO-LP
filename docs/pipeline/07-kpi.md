## 7. KPIレポート定義

### 取得データ

| データソース | 取得項目 |
|:--|:--|
| サイトリポジトリ（sitemap.xml / articles/） | 公開記事数、下書き数、カテゴリ別記事数 |
| GA4 Data API | PV、エンゲージメント時間、直帰率、ページ/セッション |
| GA4（AI参照元） | ChatGPT/Perplexity/Gemini/Copilot/Claude経由セッション数 |
| GSC Data API | 表示回数、クリック数、CTR、平均順位 |
| GSC 生成AIパフォーマンスレポート | AI Overview/AIモードインプレッション、引用ページ一覧 |
| Ahrefs API | DR、被リンク数、オーガニックKW数、推定トラフィック |
| サイトマップ | 登録URL数、最終更新日 |

### 成功パターン（kpi_feedback.md「成功パターン」に追記）

- 公開7日以内にGSC表示回数が発生した記事 → 構造・KW特性を記録
- 品質スコア117点以上の記事 → 特徴（文字数・一次情報数・Schema種類）を記録
- クラスター完成後に全体順位上昇 → クラスター効果を記録
- 【AIO】AI Overview/AIモードでインプレッション発生 → 冒頭回答・H2結論・FAQ・テーブル構造を記録し以降踏襲
- 【AIO】AI参照元セッション発生 → プラットフォームと引用された独自ファクトを記録

### 失敗パターン（kpi_feedback.md「失敗パターン」に追記）

- Vol=200以下のKWで作成 → 月間推定セッション上限が低い
- インデックス未登録 → サイトマップ・Schema・内部リンクの問題特定
- カニバリ発生KW → 対処法（統合 or 差別化）を記録
- 【AIO】順位10位以内なのにAI Overview引用なし → 冒頭回答・抽出構造・鮮度不足を特定しリライト候補に
- 【AIO】AI Overview表示クエリでCTR大幅低下 → 引用獲得+CV導線強化リライトを優先

### 翌朝パイプラインへの反映

Morning/Afternoon Pipeline 冒頭で kpi_feedback.md を読み込み:
1. 成功パターンの構造を新規記事に踏襲（AI引用獲得構造を最優先）
2. 失敗パターン該当要素を回避
3. リライト優先リストがあれば新規記事より優先してリライト実行
