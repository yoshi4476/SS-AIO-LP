## 0.1 数字を出す前に必ず通す手順（最優先・例外なし）

**1つの測り方の結果を、そのまま事実として報告してはならない。** 1つのセッションで9回誤った数字を報告し、
施策の優先順位まで誤らせた。共通の原因は「自分の測り方が正しい」と仮定したこと。

数字を1つでも出すなら、この4つを必ず通す: **別の方法で同じ数字を出す**（一致するまで出さない）／
**内訳に分ける**（指名検索・ボット・重複）／**「0件」「無い」と言う前に逆を探す**（見つかるはずの例で検出器を試す）／
**前提を口に出して確かめる**。数字が1つ崩れたら、そこから導いた結論をすべて取り下げる。

特に間違えやすい所: GSC の **query次元**の合計（少なく出る）／**末尾スラッシュ**違いの重複／**指名検索**とボットの混入／
`form_submit` と **lead_capture** の二重計上（GA4 の送信は `lead_reconcile.is_lead` で照合にだけ使う）／**問い合わせの件数は台帳の相談**（`lead_reconcile.leads`。温度が「営業」「テスト」の行＝売り込み・社内の試し送信は除き、除いた数を添える）。

**手順・落とし穴の全表・過去の誤報の実例は `/fact-checker` スキル**（`.claude/skills/fact-checker/`）。
数字・件数・制度名を報告や記事に出す作業では、頼まれていなくても呼ぶ。道具: `python scripts/data_sanity.py`。
検出器の「要対応」は元データを1件開いて確かめてから伝え、誤りは `test_detectors_do_not_misread_neighbors` に実例で足す。

## 0.2 やって分かったことは、台帳に残して次に効かせる（クライアントが増えても壊れない形）

学びを文章で積むだけでは、貯まる一方で読まれなくなる。実際 `kpi_feedback.md` は36件・11.7KBまで
膨らみ、記事を書くたびに全文を読ませていた。クライアントのサイトが増えれば破綻する。

**学びは3つに仕分ける。**

| 仕分け | 置き場 | 次からどうなる |
|:--|:--|:--|
| 機械で守れる | ゲート・検査スクリプト（台帳の `gate` に検査名を書く） | **プロンプトから外れる。** 機械が止めるので、人もAIも覚えなくてよい |
| 判断が要る | `data/lessons.jsonl` | 記事を書く直前に、関係するものだけ読ませる（12件・2,600字まで） |
| 事実の誤り | 記事の修正・一次情報の登録 | 直したら `retired` にする |

```bash
python scripts/lessons.py --brief <site>   # 記事を書く前に読ませる分（これだけ渡す）
python scripts/lessons.py --add --kind failure --phase design --rule "次からこうする" --detail "何が起きたか"
python scripts/lessons.py --review         # 週次の棚卸し（多すぎ・古すぎを知らせる）
```

**守ること**:
- サイトを指定しない学びは全サイト（クライアント含む）に効く。サイト固有は `--sites` を付ける
- **機械で守れる学びは、学びにせず検査にする。** 検査にしたら `--gate` を書いて読ませる対象から外す
- 1回の実行で積むのは1件まで。判断が要る学びが40件を超えたら週次が「要対応」で知らせる
- 読ませる量には上限がある（長いほど守られないため）。増やしたければ、まず検査に変えて減らす

**公開した後の結果からも毎週学ぶ（`scripts/learn.py --write`・週次）**: 書きながらの気づきだけでなく、
題の型ごとの実測CTR（title_patterns）・別工程の採点の一次性（score_audit）・本数を増やした分の効き（content_yield）・
28日後に戻された直し（rewrite_rollback）を、台帳へ `source=learn:*` の1行として書き戻す。
**学びごとに1行を毎週最新の数字で書き換え、根拠が条件を満たさなくなったら退役**させる（積み増さない）。
母数が足りない数字は学びにしない。`--brief` はこの実測の学びを最優先で渡す。

**実例（この仕組みで機械化したもの）**: 図解のflow型が6項目以上のとき画像が黙って5個に切られ、
タイトルと図がずれていた → `build.py` の検査にして、学びはプロンプトから外した（実際に2件検出）。

## 0.3 確かめた事実（通説を採らない）

一次情報で確認できたものだけを使う。要点: Google は **llms.txt を無視し、構造化データはAI引用に必須ではない**と公式に明言
（効くのは独自の視点・非コモディティの内容・クロールできること）。AI検索での見え方は**被リンクより言及**（YouTube 0.71・
リンク無しの言及 0.66 ＞ 被リンク 0.22。相関で DR>40 のみ）。AI Overview は**質問形のクエリで64.7%**表示。
自社データでは品質スコアは順位と逆、記事の長さは成果を分けない（長さは `depth:` で変える）。

**数字・出典・自社の検証結果・用語とプラットフォーム別の重視シグナルは `/aio-seo-specialist` スキル**
（`.claude/skills/aio-seo-specialist/references/`）。KW選定・構成・リライト・施策提案のときは呼ぶ。
補助金・助成金の制度名・金額・締切に触れるときは `/subsidy-advisor` スキルで今の状況を確かめる（制度は毎年変わる）。
