## 0. 最初に — 約束できないこと

**「確実に上位表示」は、誰にも保証できません。** 順位を決めるのはGoogleで、
アルゴリズムの更新も競合の動きもこちらの外側にあります。`scripts/growth_guard.py`
の冒頭にも同じことを書いています。

できるのは次の3つだけで、この文書はその3つを最大化するためのものです。

1. こちら側でやれることを、漏れなく、毎週続ける
2. 落ちた日に気づき、原因を切り分けて戻す
3. 他社が持っていない材料（一次データ）を増やす

「凌ぐ」を実装で表すなら、**人の判断を待たずに毎週これが回り続けること**です。
コンサルティングは提案で終わりますが、この仕組みは提案せずに実行します。

## 3. 欠けていること（実測で確認した順）

### 3.1 一次データが1本しかない — 最優先

CLAUDE.md 自身が「**AIが根拠に選ぶのは、そこにしか無い数字**。これが引用を取る
最大の手」と書いています。それなのに公開されている独立したデータページは
`/data/keizoku-ritsu-service/` の1本だけです。

`data_page.py` がGA4とGSCから自動生成する仕組みは既にあり、`/data/` に
「生成AI経由の流入」「順位ごとの実測クリック率」の2種類が載っています。
ただし**1ページに同居しており、Dataset構造化データもCSVも付いていません**。

やること:
- `/data/` の各データを独立ページに分け、Dataset + CSV + 引用用の一文を付ける
- 毎週の計測結果をそのまま追記し、時系列データにする
- これは手作業ゼロで増える。データは既に毎日取れている

### 3.2 AIクローラーが実際に来ているか測れない

robots.txt で22種を許可していますが、**静的サイトのためアクセスログが無く、
GPTBot や ClaudeBot が実際にクロールしているかを確認できません。**
引用される前提はクロールされることなので、ここが盲点です。

やること: Cloudflare の Logpush かWorkerでボットのUAを記録する。

### 3.3 競合との差分が取れない

Ahrefs MCP が未認証で、競合のどのページが何位で勝っているかを機械で取れません。
CLAUDE.md の Phase 1・3 は Ahrefs 前提の手順が書かれていますが、実行できていません。

やること: Ahrefs の認証を通す（ユーザー側の操作）。通れば Phase 1・3 が設計どおりに動きます。

### 3.4 被リンクが実質ゼロ

`data/backlinks.json` に12候補を効果順で並べてありますが、上位3件
（中小機構のURL変更申請・認定経営革新等支援機関・J-GoodTech）はすべて
**0円で、ユーザー側の申請が必要**なため止まっています。

ChatGPT系の引用はドメイン権威に強く依存するため、ここは効きます。

## 5. 毎週すでに動いていること

人が手を動かさなくても、月曜に次が回ります。

```
カニバリ検出 → 統合（auto_merge・検算11項目）
順位の見張り（growth_guard）→ 落ちた原因を4つに分解
11〜30位の押し上げ（rank_rescue → link_boost --rescue → auto_rewrite）
内部リンクの積み上がり見直し（auto_review）
盤面の空き（coverage）→ 通知
AIO基盤・会社表記・数字の信頼性の検査（findings）→ 通知
```

検査で見つかったものは `automation/logs/findings.txt` に集まり、
「要対応」が入った回だけメールが飛びます。

## 6. 守っている原則（これを外すと壊れる）

1. **数字は2通りで測って一致させてから出す**（0.1節）。1つの測り方を事実にしない
2. **検査は印字ではなく、公開を止めて初めて検査**（2026-09-23に実装）
3. **機械で守れる学びは、学びにせず検査にする**（0.2節）。読ませる量には上限がある
4. **自動修正は必ず見直しとセット**（8.6節）。1本ずつ正しくても積み上がると壊れる
5. **課金APIは設計を固めてから最後に1回**（Phase 1）
6. **割合には母数と集計期間を必ず付ける**（景品表示法）
7. **買った被リンク・自作サイトからのリンクは使わない**
