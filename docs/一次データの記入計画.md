# 一次データ 記入計画（G-ran / 補助金 / 経理BPO）

> 何を、どの記録から、どう数えるかを先に決めた計画書です。
> 記入は `python scripts/data_intake.py --sheet` で作るシートに行い、
> `intake/` に置いて `python scripts/intake_watch.py --apply` で公開されます。
>
> **決まりは3つだけです。** 母数と期間は必須。母数10未満は割合で書かない。
> 個社が分かる情報（会社名・店名・住所）は書かない。

---

## 全体の優先順

| 順 | データ | 母数の見込み | 手間 | なぜ効くか |
|:--|:--|--:|:--|:--|
| 1 | G-ran 業種別の口コミ増加 | 数百〜 | 中 | 日本語で公開例がほぼ無い。業種記事すべてで使える |
| 2 | G-ran 運用開始から効果までの日数 | 数百〜 | 中 | 「いつ効くか」は全顧客が聞く。提案でも使える |
| 3 | 補助金 不採択理由の分布 | 30 | 小 | 検索需要が大きく、公開されている分布が無い |
| 4 | 補助金 申請から交付までの日数 | 30 | 小 | 同上。母数30なら割合で書ける |
| 5 | 経理BPO 月次決算の所要日数 | 10 | 小 | 母数10なので**実数で書く**。割合は使わない |

上から順に着手すれば、手間に対する効きが最大になります。

## 1. G-ran：業種別の口コミ増加

**問い**: 業種によって、MEO運用で口コミはどれだけ増えるのか。

### 概要タブ

| 項目 | 記入内容 |
|:--|:--|
| slug | `meo-kuchikomi-zouka-gyoushu` |
| 題名 | 業種別の口コミ増加件数（◯◯店舗の集計） |
| 説明 | G-ranで運用した店舗について、運用開始前後の口コミ件数の変化を業種別に集計しました。 |
| 母数（件数） | 集計に使った店舗数 |
| 母数の単位 | 店舗 |
| 対象期間 | 運用開始日がこの範囲に入る店舗を対象（例 2023-01 〜 2026-06） |
| 集計方法・出典 | G-ranの管理画面から、運用開始日と、開始月・6か月後の口コミ件数を取り出し、業種ごとに増加数の中央値を算出 |
| 値の単位 | 件 |
| 関連カテゴリ | `meo` |

### データタブ

| 項目 | 値 | 分子 | 分母 | 判定の条件 | 判定期間・月 | 開始 | 終了 | 備考 |
|:--|--:|--:|--:|:--|--:|:--|:--|:--|
| 飲食店 | （増加の中央値） | | （店舗数） | 運用開始から6か月後の口コミ件数 − 開始時 | 6 | 2023-01 | 2026-06 | |
| 整骨院・接骨院 | | | | 同上 | 6 | | | |
| クリニック | | | | 同上 | 6 | | | |
| 歯科医院 | | | | 同上 | 6 | | | |
| 美容室・サロン | | | | 同上 | 6 | | | |

**業種は10店舗以上そろったものだけ**を行にします。10未満は「その他」にまとめるか、行ごと落とします。

### 用意するもの

G-ranの管理画面から、店舗ごとに次の4つ。業種・運用開始日・開始時の口コミ件数・6か月後の口コミ件数。
**店名は要りません。**

## 2. G-ran：運用開始から効果が出るまでの日数

**問い**: MEO運用は、始めてから何か月で順位が動くのか。

### 概要タブ

| 項目 | 記入内容 |
|:--|:--|
| slug | `meo-kouka-madeno-tsukisuu` |
| 題名 | MEO運用を始めてから順位が上がるまでの月数（◯◯店舗の集計） |
| 説明 | G-ranで運用した店舗について、主要キーワードの順位が運用開始時より上がった月を集計しました。 |
| 母数の単位 | 店舗 |
| 集計方法・出典 | 運用開始月を0として、主要キーワードの平均順位が開始時より上がった最初の月を店舗ごとに記録し、月ごとの到達割合を算出 |
| 値の単位 | % |
| 関連カテゴリ | `meo` |

### データタブ

| 項目 | 値 | 分子 | 分母 | 判定の条件 | 開始 | 終了 |
|:--|--:|--:|--:|:--|:--|:--|
| 1か月以内 | | （到達店舗数） | （全店舗数） | 主要KWの平均順位が開始時より上がった | | |
| 3か月以内 | | | | 同上（累計） | | |
| 6か月以内 | | | | 同上（累計） | | |
| 12か月以内 | | | | 同上（累計） | | |

**累計で書きます**（3か月以内には1か月以内も含む）。読者が知りたいのは「いつまでに何割か」です。

### 用意するもの

店舗ごとに、運用開始月と、順位が上がった最初の月。分からない店舗は対象から外し、その数を備考に書きます。

## 5. 経理BPO：月次決算の所要日数

**問い**: 経理を外に出すと、月次決算は何日早まるのか。

**母数が10社なので、割合では書きません。実数と中央値だけを書きます。**
機械も母数10未満の割合は止めます。

### 概要タブ

| 項目 | 記入内容 |
|:--|:--|
| slug | `keiri-bpo-getsuji-nissuu` |
| 題名 | 経理BPO導入前後の月次決算の所要日数（10社の集計） |
| 説明 | 経理BPOを導入した企業について、月次決算が締まるまでの日数を導入前後で比べました。 |
| 母数（件数） | 10 |
| 母数の単位 | 社 |
| 集計方法・出典 | 導入前3か月と導入後3か月の平均所要日数を社ごとに出し、その中央値を比較 |
| 値の単位 | 日 |
| 関連カテゴリ | `blog` |

### データタブ

| 項目 | 値 | 分母 | 判定の条件 | 備考 |
|:--|--:|--:|:--|:--|
| 導入前 | （中央値） | 10 | 月末から決算が締まるまでの日数 | |
| 導入後 | （中央値） | 10 | 同上 | |

**「◯日短縮」とは書きません。** 導入前と導入後の2行を出し、読者に引き算させます。
10社では「短縮した」と断定できないためです。備考に「10社の中央値。個社差が大きい」と書きます。

## 記入から公開までの手順

```
python scripts/data_intake.py --sheet          # 記入用シートを作る
# intake/データ記入シート.xlsx を埋める（1データにつき1ファイル）
python scripts/intake_watch.py                 # 何が起きるか見るだけ
python scripts/intake_watch.py --apply         # 登録・公開
```

不備があれば `intake/todo/` に理由つきで戻ります。
公開されると、表・棒グラフ・CSV・Dataset構造化データ・引用用の一文まで自動で作られ、
同じカテゴリの記事末に「自社の一次データ」枠が出て、一次情報として記事から使われます。

## やってはいけないこと

- 記憶や概算で数字を入れる（記録から取れない数字は入れない）
- 母数10未満で割合を書く（機械が止めますが、そもそも設計に入れない）
- 良い数字だけを選ぶ（期間や条件を後から決めると、根拠になりません）
- 個社が分かる情報を入れる（業種・規模の区分で書く）
