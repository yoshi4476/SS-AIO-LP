# 動画とSNSの手順書

> 記事と一次データから解説動画とSNS投稿文を作り、YouTubeへ上げるまでの手順です。
> **音声・画像・動画・投稿はすべて無料**で、かかるのは台本を書くぶんのトークンだけ
> （1本あたり1万トークン前後。記事1本の約3%）。

---

## 0. なぜ動画なのか

AI検索での可視性と最も強く相関するのは **YouTubeでの言及** です。

| 要因 | AI Overviews | ChatGPT |
|:--|--:|--:|
| **YouTubeでの言及** | **0.712** | **0.737** |
| リンクの無いWeb言及 | 0.656 | 0.664 |
| ブランド名のアンカー | 0.527 | 0.511 |
| 指名検索の量 | 0.392 | 0.352 |
| Domain Rating | 0.326 | 0.266 |
| 被リンク本数 | 0.218 | 下位 |

出典: Ahrefs・75,000ブランド・Spearman相関（2025-12公表）。
著者自身が「相関≠因果」と明記しており、対象はDR>40のドメインに限られます。

**当社はYouTubeの字幕を毎日ダウンロードして記事の材料にしていますが、出る側にはなっていません。**

## 1. 最初の準備（1回だけ）

### 1-1. ライブラリを入れる

```bash
pip install google-api-python-client google-auth-oauthlib
```

音声・画像・動画の道具（edge-tts・Pillow・ffmpeg）はすでに入っています。確認はこれで。

```bash
python scripts/video_make.py --selftest
```

`VIDEO_OK=yes` が出れば足りています。

### 1-2. OAuthクライアントを作る

**APIキーでもサービスアカウントでも動画は上げられません。** 投稿は
「チャンネルの持ち主が、このアプリに許可する」という形でしか通らないためです。

1. [Google Cloud Console](https://console.cloud.google.com/) を開く
   （インデックス登録で使っている既存のプロジェクトで構いません）
2. **APIとサービス → ライブラリ** で `YouTube Data API v3` を有効にする
3. **APIとサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID**
4. アプリケーションの種類は **デスクトップアプリ**
5. JSONをダウンロードし、リポジトリ直下に `youtube-client.json` の名前で置く

> **この鍵はコミットしません。** `.gitignore` に入れてください。

### 1-3. 利用者の種類を決める（ここが分かれ道）

OAuth同意画面の設定で、あとの手間が変わります。

| 設定 | 使える範囲 | 審査 | トークンの寿命 |
|:--|:--|:--|:--|
| **内部（Internal）** | 自社のGoogle Workspace内だけ | **不要** | 無期限 |
| 外部・テスト中 | 手動登録した100件まで | 不要 | **7日で失効** |
| 外部・本番 | 誰でも | **必要**（数週間） | 無期限 |

**自社3サイトだけなら「内部」にできる可能性があります。** Google Workspace を
使っていれば審査もトークンの失効もありません。

**クライアントのチャンネルへ上げるには「外部・本番」が要ります。**
`youtube.upload` は機密スコープなので、動作を録画した動画の提出と用途の説明が必要です。
「テスト中」のままだと7日ごとに全クライアントが再許可することになり、実質使えません。

### 1-4. 許可する

```bash
python scripts/youtube_upload.py --auth
```

ブラウザが開きます。**動画を上げたいチャンネルのGoogleアカウント**で許可してください。
会社のチャンネルが別アカウントなら、そちらでログインします。

`youtube-token.json` ができれば完了です。以降はブラウザ不要。

```bash
python scripts/youtube_upload.py --check
```

`YT_OK=yes` を確認します。

## 2. 毎回の手順

### 2-1. 動画を作る

```bash
# 一次データから（数字が主役の動画。棒グラフつき）
python scripts/video_make.py --from-data meo-kouka-madeno-tsukisuu

# 記事から（見出しと1文結論を並べた解説動画）
python scripts/video_make.py --from-article ai-hojokin-fusaitaku-riyu
```

`automation/video/<slug>.mp4` にできます。実測で一次データは約90秒、記事は約2分45秒。

**作り終えると、台本の合計と動画の長さが一致しているかを機械が確かめます。**
1秒を超えてずれていれば書き出しを中止します。

### 2-2. 中身を見る

**必ず再生してください。** 特に次の3つ。

- 数字の読み間違い（`read_text()` の置き換えで直らないもの）
- 字幕が画面からはみ出していないか
- 棒グラフの強調行が、読み上げと合っているか

読み方を直すときは `scripts/video_make.py` の `READ_AS` に1行足します。

### 2-3. YouTubeへ上げる

```bash
python scripts/youtube_upload.py automation/video/<slug>.mp4 --slug <slug>
```

**既定は限定公開です。** チャンネルで確認してから公開に切り替えてください。
最初から全体公開にするなら `--public` を付けます。

概要欄は自動で組み立てます。記事URLが先頭に入り、一次データなら母数・期間・集計方法まで載ります。

### 2-4. SNSの投稿文を作る

```bash
python scripts/social_post.py --new --limit 10 --md
```

`automation/logs/social_queue.md` に、X・Facebook・Threads・LinkedInの4媒体ぶんが
記事ごとに並びます。コピーして貼るだけです。

```bash
python scripts/social_post.py --done <slug>    # 貼り終えたら消す
```

## 3. なぜSNSは自動投稿にしないのか

| 媒体 | 費用 | 障害 |
|:--|:--|:--|
| **X** | **1投稿$0.20**（リンク付き） | 2026-02-06に新規の無料枠が廃止された |
| Facebook | 無料（25投稿/日） | 他社ページへの投稿はMetaの審査が必要 |
| Threads | 無料（250投稿/日） | 同上。審査に数週間 |
| LinkedIn | 無料（約100回/日） | トークンが60日で失効 |

Xは3サイト×2本/日で月36ドル、10社に増やすと月120ドルです。

**投稿文を作って渡す形にすれば、権限も審査も課金も要りません。**
クライアントは自分のアカウントで貼るだけで、こちらは何も預かりません。
クライアントが増えても設定は増えません。

自動投稿に切り替えるのは、**手で貼って効果が出ると分かってから**で十分です。

## 4. クライアントへ展開する

### 4-1. 審査は1回、許可は各社1回

| 作業 | 単位 | 誰が |
|:--|:--|:--|
| OAuthクライアントを作る | アプリごとに1回 | 当社 |
| Googleの審査 | アプリごとに1回 | 当社（数週間） |
| Metaの審査（SNSも自動化する場合） | アプリごとに1回 | 当社（数週間） |
| チャンネル・ページの許可 | **クライアントごと** | クライアントが1クリック |

### 4-2. クライアントごとの設定

`sites/<id>.json` に受け皿があります。

```json
"youtube": {
  "token": "credentials/yt-<id>.json",
  "channel_name": "〇〇株式会社 公式",
  "voice": "ja-JP-NanamiNeural",
  "rate": "+5%"
},
"social": { "x": "@...", "facebook_page": "...", "threads": "", "linkedin": "" }
```

**声と読み上げ速度もクライアントごとに変えられます。** 使えるのは
`ja-JP-NanamiNeural`（女性）と `ja-JP-KeitaNeural`（男性）の2種類です。

### 4-3. おすすめの順番

**まず自社3サイトで3か月回してください。**

理由は2つあります。審査が不要か軽く済む可能性があること。そして
**効果が実測できていない段階で数週間の審査に時間を使うのは順序が逆**だからです。

3か月あれば `brand_search.py` で指名検索が増えたかを測れます。
効いたと分かってから展開すれば、提案の根拠も持てます。効かなければ審査を受けずに済みます。

## 5. 品質のための決まり

### 5-1. 本文に無いことを言わせない

台本は**記事のH2と1文結論、一次データの登録済みの数字からの抜き出しだけ**で作ります。
要約をAIに書き直させると、本文に無い話が混ざって事実と違う動画になります。

### 5-2. スライドは音声の実測に合わせる

字数から秒数を推測しません。実測で26字が5.40秒、24字が4.87秒と比例しませんでした。
1区間ずつ音声を作り、`ffprobe` で測り、その秒数でスライドを出します。

### 5-3. 1区間は54字まで

引用用の一文をそのまま読ませたら19秒、集計方法は25秒になり、その間スライドが
1枚も動きませんでした。句点と読点で切っています。

### 5-4. 音声はWAVでつなぐ

mp3のまま `-c copy` でつなぐとフレーム境界がそろわず、区間ごとに数十ミリ秒ずつ
ずれていきます。いったんWAVに開いてからつなぎます。

## 6. うまくいかないとき

| 症状 | 原因と直し方 |
|:--|:--|
| `長さを測れません` | ffprobe の出力を `text=True` で読んでいる。`encoding="utf-8"` を指定する（このリポジトリのパスに日本語が入っているため必ず起きる） |
| 数字や略語を1文字ずつ読む | `READ_AS` に置き換えを足す。日本語に隣接する英字に `\b` は効かないので `(?<![A-Za-z])` を使う |
| `音声と映像がずれています` | 台本の合計と動画の長さが1秒以上違う。音声の連結がmp3のままになっていないか確認 |
| `youtube-token.json がありません` | `--auth` を実行する |
| 7日でトークンが切れる | OAuth同意画面が「テスト中」のまま。「内部」か「本番」に変える |
| `日本語フォントが見つかりません` | YuGothB.ttc / meiryob.ttc の有無を確認 |

## 7. 使うコマンドの一覧

```bash
python scripts/video_make.py --selftest                     # 道具の確認
python scripts/video_make.py --from-data <slug>             # 一次データから動画
python scripts/video_make.py --from-article <slug>          # 記事から動画
python scripts/youtube_upload.py --check                    # 鍵と枠の確認
python scripts/youtube_upload.py --auth                     # 初回の許可
python scripts/youtube_upload.py <mp4> --slug <slug>        # 限定公開で上げる
python scripts/youtube_upload.py <mp4> --slug <slug> --public
python scripts/social_post.py --new --limit 10 --md         # 投稿文を作る
python scripts/social_post.py --done <slug>                 # 貼ったら消す
```

YouTubeの枠は `videos.insert` が1回1ユニット・1日100回までです
（2026-06-01から専用枠になり、それ以前の1,600ユニット・1日6本から大きく緩和されました）。
読み取りの10,000ユニットとは別枠なので、他の処理を圧迫しません。
