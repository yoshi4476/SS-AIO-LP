# 一次データの増やし方

> AIが回答の根拠に選ぶのは「そこにしか無い数字」です。別工程の採点でも、
> 一次性が最も弱い軸でした（中央値7.0/10・2026-09-23）。
> ここでは増やす手段を、手間の少ない順に並べます。

## いま公開しているもの（5本）

| データ | 母数 | 出どころ | 更新 |
|:--|--:|:--|:--|
| 検索順位ごとの実測クリック率 | 表示7,015回 | Search Console | 週次・自動 |
| 記事を公開してから検索に出るまでの日数 | 372本 | Search Console + 原稿 | 週次・自動 |
| 検索順位ごとの内部リンク本数 | 196本 | Search Console + 原稿 | 週次・自動 |
| 生成AI経由の流入 | 42セッション | GA4 | 週次・自動 |
| 運用サービス別の契約継続率 | 契約99件 | 契約一覧（手入力） | 随時 |

`python scripts/data_auto.py --write` で上4本が作り直され、
表・グラフ・CSV・Dataset構造化データ・引用用の一文まで自動で作られます。

---

## 方法1: すでに測っているものを公開する（手間ゼロ・最優先）

**一番早い増やし方は、測っているのに公開していない数字を出すことです。**
このサイトは毎日GSCとGA4を計測しており、その結果自体が一次データになります。

追加できる候補（`scripts/data_auto.py` に関数を1つ足すだけ）:

| 候補 | 何が言えるか | 必要なもの |
|:--|:--|:--|
| 施策の効果（対照群あり） | 内部リンクを足すと順位は動くのか | `effect_ab` の記録が貯まれば |
| 業種別の順位分布 | どの業種が取りやすいか | いまの母数で出せる |
| 記事の長さと順位 | 長いほど良いは本当か | 7,000字以上が4本。母数待ち |
| 図解の有無と順位 | 図解は効くのか | いまの母数で出せる |
| 公開時刻と初速 | 何時に出すと早く拾われるか | 半年ぶん貯まれば |

**守ること**: 母数10未満は割合で書かない。集計期間を必ず添える（景品表示法）。
`add_fact` と `data_intake` が機械で止めます。

## 方法2: 運用しているサービスの記録を出す（手入力・効きが大きい）

自社サイトの計測より、**実際の顧客運用のデータのほうが強い**です。
他社がまず持っていません。

| 持っているもの | 出せる数字の例 | 注意 |
|:--|:--|:--|
| G-ran のMEO運用（通算3,200店舗以上） | 業種別の順位変動、口コミ増加の分布、運用開始から効果までの日数 | 個社名は出さない。業種と母数だけ |
| AI導入補助金の支援 | 申請から交付までの日数、不採択理由の分布、必要書類でつまずく箇所 | 採択率は母数と期間必須 |
| 経理BPO（10社） | 月次決算の所要日数の変化、処理件数 | 母数10なので実数で書く |

**入れ方**: `python scripts/data_intake.py --sheet` でシートを作り、
埋めて `intake/` に置き、`python scripts/intake_watch.py --apply`。
1枚埋めれば、ページ・CSV・構造化データ・引用用の一文まで自動で作られます。

**これが一番効きます。** 3,200店舗の運用記録は、日本のMEO・AIO業界で
公開されている例がほとんどありません。業種別に切り分けるだけで、
他社の記事が数字を探すときの出典になります。

## 方法3: 新しく取りに行く（手間はかかるが独自性は最大）

| 手段 | 母数の目安 | 手間 | 効き |
|:--|--:|:--|:--|
| 既存顧客へのアンケート | 30〜100 | 中 | 大 |
| 支援先への聞き取り（数社を深く） | 5〜10 | 中 | 中（事例として強い） |
| 業界向けの公開アンケート | 100〜 | 大 | 最大（報道されうる） |

アンケートを出すなら、**答えが数字になる質問だけ**にします。
「満足していますか」ではなく「導入前後で問い合わせは月何件変わりましたか」。
母数が10を割ると割合で書けないため、30件は集める設計にします。

## 増えたかどうかの見方

```
python scripts/data_auto.py          # 自動で作れる分を確認
python scripts/guarantee.py          # 一次データの公開本数が達成率に入る
python scripts/score_audit.py --compare   # 一次性の点数が上がったか
```

一次性の点数（10点満点）が中央値8以上になれば、
「そこにしか無い情報がある記事」が標準になったと言えます。
いまは7.0です。
