# CLAUDE.md 0.1 の原文（2026-10-03 にスキルへ移設したときの控え）

## 0.1 数字を出す前に必ず通す手順（最優先・例外なし）

**1つの測り方の結果を、そのまま事実として報告してはならない。**

実際に1つのセッションで9回、誤った数字を報告した。どれも30秒の再確認で防げた。
誤りの上に次の判断を重ねたため、施策の優先順位まで誤らせた。

| 報告した内容 | 根拠にしたもの | 実際 |
|:--|:--|:--|
| CTR1.6%が課題 | GSCのquery次元 | page次元では111クリック（query次元は検索数の少ない語を返さない） |
| コーポレートは73%達成 | クリック総数 | 17回中15回が指名検索。記事の力ではない |
| 転換率5.7% | form_submit + lead_capture | 同じ送信で両方発火する。二重計上で実際は4件 |
| 9%はGoogle広告 | GA4の媒体名 | 広告は未出稿。国も取れない無効な流入だった |
| JSが同期読み込み | 正規表現（srcが先と仮定） | async は src の前にあった |
| CTAゼロ58本 | `cta-button` クラスだけを数えた | 別のクラス名で導線があった |
| 191本が導線なし | 原稿のMarkdownを見た | 生成HTMLには全て入っていた（テンプレートが挿入） |
| H1がAIに読まれない | タグを空白に置換して抽出 | タグを除去すれば正しい文だった |
| 前月比の計算方法が混在 | 「セッション」で文字列検索 | 「AI経由セッション」まで拾っていた（別の指標） |
| 押し上げのリンクが壊れる | `\s*` で行頭の空白を見た | `\s` は改行にも一致し、空行をはさんだ箇条書きまで「直結」と数えた |
| 問い合わせを取りこぼした | GA4 の form_submit を数えた | トップ・記事の「30秒診断」のURL入力も form_submit になる。問い合わせではなかった |

**共通しているのは1つだけ。「自分の測り方が正しい」と仮定したこと。**
対象の性質ではなく、道具の癖を見ていた。

### 数字を1つでも出すなら、この4つを必ず通す

| # | やること | 防げる誤り |
|:--|:--|:--|
| 1 | **別の方法で同じ数字を出す**。一致しなければ、一致するまで報告しない | 道具の癖・抽出方法の癖 |
| 2 | **内訳に分ける**。合計だけで語らない（指名検索・ボット・重複を分離する） | 水増し・二重計上 |
| 3 | **「0件」「全部」「無い」と言う前に、逆を探す**。検出できないことは、存在しないことではない | 1つの書き方しか見ていない |
| 4 | **前提を口に出して確かめる**（広告は出しているか／設定はどこにあるか） | 前提の思い込み |

### 「見つからなかった」と「無い」は違う

`grep` が0件でも、それは「その書き方では無い」であって「存在しない」ではない。
**必ず、見つかるはずの例で検出器を試してから**、0件を報告する。

### 誤った数字を、次の判断に使わない

数字が1つ崩れたら、そこから導いた結論をすべて取り下げる。
「概ね合っている」で先に進むと、誤りが施策の優先順位まで運ばれる。

### 使う道具

```bash
python scripts/data_sanity.py      # 二重計上・無効流入・GA4とGSCの食い違い・指名検索の割合
```

ここで注意が出た数字は、原因を確かめるまで報告しない。

### GSCとGA4で、特に間違えやすいところ

| 落とし穴 | 正しい扱い |
|:--|:--|
| GSCのquery次元 | 検索数の少ない語を返さない。**合計は次元なしかpage次元で取る** |
| GSCのpage次元 | 末尾スラッシュ違いで同じページが2行に分かれる。**合算する** |
| URLの末尾だけをslugにする | 別カテゴリの同名ページが1つに潰れる。**URLごと鍵にする** |
| GA4のクリック・セッション | ボット（国が取れない）と指名検索を**必ず分けて見る** |
| 1回の送信で飛ぶイベント | `form_submit` と `lead_capture` は**同時に飛ぶ。足さない** |
| `form_submit` の中身 | **どのフォームでも出る**（診断のURL入力・購読も）。問い合わせは `lead_capture` / `generate_lead` と `/contact` の送信だけで数える（`lead_reconcile.is_lead`） |

### 検出器の「要対応」を人に伝える前に（2026-10-02 追加）

検出器が出した「取りこぼし」「混在」「壊れている」は、**元のデータ（どのページの・どのフォームの・どの文の）を1件開いて確かめてから**伝える。
検出器の誤りは、見つけたら直すだけでなく `tests/test_gates.py` の `test_detectors_do_not_misread_neighbors` に実例として足す（ゲートが毎回確かめる）。
