# 数字と事実の検算

このプロジェクトでは、1つの測り方の結果をそのまま事実として報告し、1つのセッションで9回誤った。
どれも30秒の再確認で防げた。誤りの上に次の判断を重ね、施策の優先順位まで誤らせた。
原因は毎回同じで、**「自分の測り方が正しい」と仮定したこと**。対象の性質ではなく、道具の癖を見ていた。

このスキルの仕事は、数字や断定を外に出す前に、その仮定を崩してみること。

## 出す前に通す4つ

| # | やること | 防げる誤り |
|:--|:--|:--|
| 1 | **別の方法で同じ数字を出す。** 一致しなければ、一致するまで出さない | 道具・抽出方法の癖 |
| 2 | **内訳に分ける。** 合計だけで語らない（指名検索・ボット・重複・取り下げ済みを分ける） | 水増し・二重計上 |
| 3 | **「0件」「全部」「無い」と言う前に、逆を探す。** 見つかるはずの例で検出器を試してから0を報告する | 1つの書き方しか見ていない |
| 4 | **前提を口に出して確かめる**（広告は出しているか／設定はどこにあるか／その制度は今も公募しているか） | 前提の思い込み |

「別の方法」は本当に別でなければ意味がない。同じAPIを同じ次元で2回叩くのは別の方法ではない。
例: GSC の合計 → 次元なしの合計と page 次元の合計。HTML の導線 → 原稿ではなく生成HTMLを数える。
文字列検索の結果 → ブラウザで描いて数える（表のはみ出しは 375px で描いて scrollWidth を測る）。

## 「見つからなかった」と「無い」は違う

grep が0件でも、それは「その書き方では無い」であって「存在しない」ではない。
検出器を作ったら、**見つかるはずの例（悪い例）を拾うこと**と、**見つかってはいけない例（良い例）を拾わないこと**の両方を確かめる。
片方だけでは、常に0を返す壊れた検出器も、何でも拾う検出器も通ってしまう。
検出器が「要対応」と出したら、元のデータを1件開いて本当にそうかを確かめてから伝える。

## 動かなかった検査を「問題なし」にしない

取得に失敗した・例外で止まった・対象が0件だった、は「問題なし」ではなく「分からない」。
`*_OK=yes` や「0件」「-100%」を出してよいのは、検査が実際に動いて対象を見たときだけ。
分からないときは `unknown` と書き、何が取れなかったかを書く。

## 数字が1つ崩れたら

そこから導いた結論をすべて取り下げる。「概ね合っている」で先に進むと、誤りが施策の優先順位まで運ばれる。
取り下げたことは、相手に明示する（黙って直さない）。

## 間違えやすいところ（実際に間違えた）

| 落とし穴 | 正しい扱い |
|:--|:--|
| GSC の query 次元 | 検索数の少ない語を返さない。**合計は次元なしか page 次元で取る** |
| GSC の page 次元 | 末尾スラッシュ違いで同じページが2行に分かれる。**合算する** |
| URL の末尾だけを鍵にする | 別カテゴリの同名ページが潰れる。**URLごと鍵にする** |
| GSC の endDate | 今日は渡せない。月初の前月分の終了日に今日を入れない |
| GA4 のクリック・セッション | ボット（国が取れない）と指名検索を**分けて見る** |
| `form_submit` と `lead_capture` | 1回の送信で同時に飛ぶ。**足さない** |
| `form_submit` の中身 | 診断のURL入力・購読でも出る。問い合わせは `lead_reconcile.is_lead` の条件だけで数える |
| 「セッション」で文字列検索 | 「AI経由セッション」まで拾う。似た名前の指標が同じ場所にないか確かめる |
| 正規表現の `\s*` | 改行にも一致し、空行をまたいで「直結」と数える |
| 上限で切った件数 | 「60語」と書いたら実は293語だった。切ったなら「上位60語」と書く |
| 台本・記事の「◯つ」 | 言った数と、実際に並べた項目の数を数え合わせる（「6つ」と言って5点で終わった動画が公開された） |
| 制度・料金・法令 | 知っている内容は古い前提で扱う。一次情報で今の状況を確かめ、確認日を添える（補助金なら /subsidy-advisor） |

さらに詳しい実例は [references/past-misreports.md](references/past-misreports.md)（判断に迷ったときに読む）。

## 使う道具

```bash
python scripts/data_sanity.py      # 二重計上・無効流入・GA4とGSCの食い違い・指名検索の割合
python scripts/lessons.py --brief <site>   # その作業に関係する過去の学び
```

data_sanity で注意が出た数字は、原因を確かめるまで報告しない。

## 出し方

数字を報告するときは、数字ごとに次の形で根拠を添える（相手が検算できるように）。

```
◯◯は N です。
- 方法A: <どこから・どの条件で> → N
- 方法B: <別の取り方> → N（一致）
- 内訳: <指名 x / ボット y / 重複 z を除いた>
- 前提: <確かめた前提。確かめられなかったものは「未確認」と書く>
```

一致しなかったら、数字を出さずに「AとBが合わない。理由を調べている」と書く。
記事・台本の場合は、本文の数字ごとに出典（site_brief の一次情報・公的資料のURL・記事の該当行）が言えるかを確かめ、言えない数字は消す。

## 直したら、機械に渡す

同じ誤りを2回しないために、見つけた誤りは「気をつける」で終わらせない。
機械で見分けられるなら `tests/test_gates.py`（または tests/gates_history_*.py）に、悪い例と良い例つきの検査として足す。
判断が要るものだけ `python scripts/lessons.py --add ...` で台帳へ。
