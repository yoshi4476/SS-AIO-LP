# オリジナルとして認められる記事

**Google は「AIが書いたか」では評価しない。** 見ているのは、独自の経験と視点・一般論に留まらない中身・読者の役に立つか・大量生成でないか（Google の AI 最適化ガイドとスパムポリシー。数字と出典は /aio-seo-specialist の references）。
だから、AIの文章を人の文章に見せかける加工（検出をすり抜ける言い換え・わざと崩す文体）はしない。効かないうえ、大量生成の不正とみなされる危険がある。**中身でオリジナルにする。**

## 書く前に決める3つ（構成の段階で）

1. **この記事にしか無いもの**を2つ以上決める。候補の順:
   - 登録済みの一次情報（`scripts/facts.py`。母数と時期つき）
   - 登録済みの本当の体験（`data/experiences.json`。site_brief の「一人称で書いてよい体験」）
   - 一次資料（法令・公募要領・公式ドキュメント）を読み比べて分かる、まとめ記事に無い違いや落とし穴
   - 判断の基準（「◯◯なら A、△△なら B」と、そう判断する理由）
2. **検索上位に無い節を2つ以上**入れる（`kw_serp.py --brief` の上位の見出しと比べる）。上位と同じ見出しの並びを写さない
3. **誰が書いたか**: 著者・監修者の立場から言えることを書く（当社が実際に扱っている範囲・扱っていない範囲）

## 書くときの決まり

- **体験談を作らない。** 一人称の出来事は、登録された体験（目印の key を文に入れる）か一次情報からだけ書く。
  登録が無いときは、出来事ではなく「当社の判断とその理由」として書く（例: 「当社では、担当者を専任で置けない場合は外部委託を勧めています。更新が止まりやすいためです」）
- **決まり文句を使わない**: 「私たちが相談を受ける中でも」「何度も聞いてきました」「ある医院では」。score_check が止める（`originality.py`）
- **数字は出典が言えるものだけ**（/fact-checker）。割合は母数と期間をつけ、母数10未満は実数で
- **一般論で終わらせない**: 各節に「だから読者は何をすればよいか」を1つ入れる
- **同じ型の記事を量産しない**: 業種を入れ替えただけの構成にしない。その業種・地域にしか無い事情で書き分ける
- **人らしさは中身で出す**: 具体的な条件・順番の理由・失敗の原因と避け方・やらない判断。語尾をわざと崩したり誤字を入れたりしない

## 公開後に人が確認するときに見る点（5〜10分）

| 見る点 | 問題の例 | 直し方 |
|:--|:--|:--|
| 体験談が本当か | 覚えの無い相談・事例 | 消す、または本当の体験を data/experiences.json に登録して書き直す |
| 数字の出典 | 出どころの分からない割合 | 一次資料のリンクを足すか消す |
| 当社が言える範囲か | 扱っていないサービスの断言 | 範囲を正しく書き直す |
| 上位に無い中身があるか | どこにでもある説明だけ | 判断の基準・落とし穴・一次情報の節を足す |
| 表現 | 「必ず」「No.1」、医療・補助金の誇大 | 条件つきの言い方に |

## 体験を登録する（本当にあったことだけ）

```bash
python scripts/originality.py --add --site ai-lab --key "<記事の文に入れる目印>" --text "<何があったか>" --when 2026-09
python scripts/originality.py --list --site ai-lab
python scripts/originality.py --check <slug>        # 1本の決まり文句と、上位との差を見る
```

お客様の社の体験は、ここではなく非公開の置き場（brief.json の事例）に置く。
