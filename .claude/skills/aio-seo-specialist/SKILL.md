# AI検索とSEOの実務

このプロジェクトは3サイト（AI集客ラボ・コーポレート・補助金）と受託先の記事を、KW選定から公開後の改善まで自動で回している。
判断の土台は「通説」ではなく、**一次情報で確かめた事実と自社の実測**。業界記事が広めている主張の多くは裏付けが取れなかった。
提案や記事で通説を採ると、クライアントの予算を効かない施策に使わせることになる。

## 最初に押さえる事実（2026年9月時点で確認済み）

**Google が公式に否定していること**（AI最適化ガイド）: llms.txt は無視する／構造化データはAI引用に必須ではない（AI専用スキーマも無い）／内容を細かく刻む必要は無い／AI向けの特別な書き方は無い／GEO・AEOの技法は効かない。
**効くと明記されているのは3つ**: 独自の視点（一次体験）・一般論に留まらない内容・クロールできること。
リッチリザルト目的の構造化データは引き続き有効なので、出力は変えない（「AI対策として」売らない）。

**外部の実測で効く順**（Ahrefs・75,000ブランド・相関）: YouTubeでの言及 0.71〜0.74 ＞ リンクの無いWeb言及 0.66 ＞ ブランド名のアンカー ＞ 指名検索 ＞ DR ＞ 被リンク本数 0.22。
被リンクより「言及」が約3倍効く。ただし相関で、対象は DR>40。**当社が条件を満たすとは限らない**と添える。

**AI Overview の表示率**は全体13.7%、**質問形のクエリでは64.7%**。引用ドメインの約30%は1ページ目に出ていない（順位と別の選び方がある）。

数字の出典と、自社データの検証結果（品質スコアは順位と逆・記事の長さは成果を分けない 等）は [references/facts-2026.md](references/facts-2026.md)。提案書や記事に数字を書くときは必ずそこから引き、出典URLを添える。

## 判断の手順

### 狙う語を決める
1. `python scripts/kw_guard.py "<KW>" --site <site>` — 終了コードで決める（0=着手可／1=要差別化／2=書かない・既存を書き足す）。目視で代えない。タイトルが似ていなくても、GSC で既に順位を持つ自社ページがあれば食い合う
2. `python scripts/kw_intent.py "<KW>"` — 開かないと済まない語か。同じ順位でもCTRは5倍違う。「例文・とは・一覧・診断」は検索結果で用が済むので、検索結果に出せないもの（失敗例・違反例・自社の一次データ）を題と冒頭に置けるときだけ書く
3. 買い手の語（外注・比較・費用）を、自分でやる人の語より先に置く。目的はリード

### 「引用されない」「伸びない」を切り分ける（この順に）
1. 順位は10位以内か — 圏外なら先に通常のSEO（AI引用の前提は上位表示）
2. クローラーが届くか — robots.txt と、Cloudflare の AIクローラー既定ブロック（2026-09-15開始）・WAF の403/429
3. 抽出できる形か — 冒頭の断言・H2直下の1文結論・表・FAQ
4. 鮮度 — dateModified が6か月以上前なら更新（本文が変わらないのに日付だけ動かさない）
5. 独自性 — まとめ直しになっていないか。自社の一次データ・失敗事例があるか
6. それでも駄目なら言及（YouTube・リンク無しの言及・指名検索）の中長期の積み上げ

### 数字を読むとき
GSC・GA4の数字は道具の癖で簡単に誤る（query次元の合計・末尾スラッシュ・二重計上・指名検索の混入）。
結論を出す前に /fact-checker の4つの確認を通す。

## 提案・記事で言わないこと
- 「llms.txt を置けばAIに引用される」「構造化データでAI対策」— 公式に否定済み
- 「◯位を保証」「必ず引用される」— 順位も引用も Google と各AIが決める。約束できるのは打ち手を効く順に回すことと、遅れを数字で知らせること
- 自社の小さい実測（表示数百・クリック0 など）を一般化した数字 — 母数と期間を必ず添え、10未満は割合にしない
