# 補助金・助成金の制度確認と申請実務

補助金は毎年、名前・枠・上限額・補助率・対象経費が変わり、統合や受付終了もある。
**手元の知識は古い前提で扱う。** 2026-10-03 には、統合済みの「ものづくり補助金」と受付終了の「事業再構築補助金」を
現行の制度として束ねかけ、ユーザーの指摘で直した。古い制度で申請を勧める記事は、読者に実害を出す。

## 書く・答える前に確かめること

1. **制度の現況**: 今年度も公募しているか／名前が変わっていないか／統合・終了していないか
2. **今の公募回と締切**: 「第◯回」「◯月◯日締切」。締切が過ぎた回を「募集中」と書かない
3. **金額と率**: 上限額・補助率・下限額は枠ごとに違う。枠の名前とセットで書く
4. **対象と対象外**: 対象者（個人事業主を含むか）・対象経費・併用の制限

確かめる先は次の順。上ほど優先し、下の情報だけで断定しない。

| 優先 | 情報源 | 例 |
|:--|:--|:--|
| 1 | 公募要領（PDF）・事務局の公式サイト | it-shien.smrj.go.jp（デジタル化・AI導入）、jizokukahojokin.info / jizokukanb.com（持続化） |
| 2 | 所管官庁の発表 | chusho.meti.go.jp（中小企業庁）、厚生労働省（雇用関係助成金） |
| 3 | 申請窓口 | jGrants、ミラサポplus、自治体の公式ページ |
| 4 | 専門家の解説記事 | 1〜3が見つからないときの手がかり。数字はここから引かない |

確かめた内容には**確認日**を添える（例:「2026年10月時点」）。記事なら冒頭の鮮度表記と本文の該当箇所の両方に入れる。

現時点で確かめた制度の状況は [references/program-status.md](references/program-status.md)。
**そこに書いてある内容も、確認日から3か月を過ぎていたら確かめ直す**（公募回は数か月で変わる）。

## 制度が終わった・変わったとき（台帳と機械にも反映する）

制度の終了・統合・改称を確かめたら、記事を直すだけで終わらせない。

1. `references/program-status.md` を更新する（状況・確認日・出典URL）
2. 受付が終わった制度は `sites/subsidy.json` の `ng_terms` に足す（狙う語の段階で弾かれる）
3. `tests/test_gates.py` の `RETIRED_PROGRAMS` に終了日とともに足す（新しく狙う記事を止める）
4. 改称・統合なら、旧名で検索する読者のために、記事の冒頭で「旧◯◯は◯年度から◯◯に統合／改称」と書く（旧名は検索され続ける）
5. 既存記事の古い記述は `/aio-seo-specialist` の鮮度更新（`auto_rewrite --kind fresh`）の対象に入れる

## 書き方の決まり

- **採択を約束しない**: 「必ず採択」「誰でももらえる」は書かない。審査があり、採択は事務局が決める
- **採択率・実績は母数と期間つき**: 「2025年4月〜2026年3月に支援した42社のうち38社が採択（90.5%）」の形。母数10件未満は割合にせず実数で（景品表示法・`add_fact` が機械で止める）
- **公的な数字は出典つき**: 全体の採択率（例: 第19回は申請16,576件・採択7,819件）は所管の発表から引き、回を明記する
- **申請実務の言葉で書く**: 交付申請・事業計画書・gBizIDプライム・見積書・実績報告・入金までの立替のように、読者が実際に手を動かす単位で書く。「着金はいつか」「立替が要る」は読者が最も困る点
- **専門家の判断が要る所は線を引く**: 個別の要件該当・税務の扱いは「事務局・認定支援機関・税理士に確認」と添える

## 迷ったら

数字を出す前は `/fact-checker` の4つの確認を通す。
狙う語の選定・食い合い・記事の構成は `/aio-seo-specialist` の手順に従う。
